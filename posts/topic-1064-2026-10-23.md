# 一天五六个会话、每次两三百字背景介绍：装上 ECC 后，Claude Code 自己长记性了

用 Claude Code 写代码的人，估计都被同一件事折磨过：昨天会话里聊得明明白白的规范，今天新开一个窗口，它忘得干干净净。项目背景重新介绍，「我们用 pnpm 别用 npm」重新叮嘱，连「错误处理走那个统一函数」都得再说一遍。

这事有个唬人的名字，叫上下文工程。说人话就是：把该给的信息，在该给的时候塞给模型。AI 编程发展到今天，写代码本身早不是瓶颈，瓶颈是每次都要重新教它。

为了治这个病，我前后用过三种方案：裸用硬扛、手写 CLAUDE.md、最近换上的 ECC。今天摊开比一比，你自己看适合哪个。

## 方案一：裸用 Claude Code

先说清楚，裸用不是不能干活。模型够聪明，你把背景交代清楚，它一次也能干得像模像样。问题出在「每一次」。

我算过一笔账：光是解释这个项目是什么、技术栈、哪些规矩碰不得，一次就得敲两三百字。我一天开五六个会话，光背景介绍就够写一篇作文。

更气人的是，它不是没听懂，是压根没听到。你哪条忘了叮嘱，它就按自己的默认审美来：错误处理自己发明一套，文件想放哪放哪。代码能跑，但风格像两个人写的，严格来说，也确实是两个人写的。

如果你只是偶尔写个一次性脚本，写完就扔，那裸用完全够，别折腾。

## 方案二：手写 CLAUDE.md

Claude Code 支持在项目根目录放一个 CLAUDE.md，每次会话自动读进去。用 Cursor 的同学对应的是 .cursorrules，一个道理。文件大概长这样：

```
# 项目规范
- 包管理只用 pnpm,禁止 npm install
- 组件放 src/components,页面级组件放 src/pages
- 错误处理统一走 utils/errors.ts 里的 wrapError,不要自己写 try-catch
- 提交信息用中文,格式:模块名: 干了什么
```

效果立竿见影，这没得说。会话之间它确实记住了，不用重复叮嘱。

但用久了，坑就露出来了。

一是这文件只装你「想得起来写」的东西。项目是活的，规范天天在长，而你会忘记更新它。我有个项目，CLAUDE.md 里写的还是三个月前的目录结构，AI 一直拿着旧地图走路，我两周后才发现不对劲。

二是它只管规矩，不管经验。上次解决「Excel 大数据量导出内存爆掉」，踩出来的分片方案是真金白银换来的。下次遇到类似需求，它照样从零想一遍。CLAUDE.md 存得住规则，存不住解法。

项目一两个、规范稳定、人又勤快，这方案性价比很高。三条缺一条，你就得受点罪。

## 方案三：给 Claude Code 装 ECC

ECC 是我最近在 GitHub 上蹲到的开源项目，思路一句话：把上面那些手动维护的活儿，变成自动积累。它给 Claude Code（也支持 Cursor）加三样东西：记忆、技能库、安全沙箱。

记忆管跨会话记住规范和风格。跟 CLAUDE.md 的区别在于，它不是等你写，而是会话结束后自己把「这次学到的项目事实」沉淀下来。你纠正过它一次「我们不用 axios，用项目里封装好的 request」，下次它自己就懂了。你骂它的每一句，都变成了它的长期记忆，听着有点卑微，但确实好用。

技能库管复用解法。那个 Excel 分片导出的方案，会变成一条技能存起来，下次碰到类似需求直接调用，不再重新发明轮子。

沙箱管别乱来。AI 编程最让我紧张的就是它动不动要「我跑个命令帮你验证一下」。ECC 会把危险操作拦下来，问过你才放行。不敢让它直接碰生产环境的，装了踏实很多。

## 装起来不复杂

前提是机器上已经有 Claude Code，没有的话终端里跑：

```
npm install -g @anthropic-ai/claude-code
```

然后去 GitHub 搜 ECC，照着 README 装。大致流程：把仓库拉下来跑安装脚本，cd 到项目根目录初始化一次，它会建个配置目录存记忆和技能，中间问你几个问题，沙箱开不开、记忆放全局还是跟着项目走。拿不准就一路默认，后面都能改。最后重启 Claude Code，新会话里问一句它记不记得项目的错误处理规范，装没装上一试便知。

具体命令我就不写死了，这类项目更新很勤，README 永远比我这篇文章新，照官方文档抄最稳。

## 同一个需求，装 ECC 前后

拿上周的真实需求说事：给后台订单列表加「导出 Excel」。

装 ECC 之前，我的开场白是这样的：这是 Next.js 项目、用 pnpm、导出统一用 exceljs 别引新库、错误处理走 wrapError、文件放 src/services……两三百字打出去，交上来的代码还是错了两处——自己发明了个 try-catch 写法，文件给我塞进了 src/lib。

装 ECC 之后，同一个需求，我就一句话：「给订单列表加导出 Excel」。它直接用了 exceljs，因为上上个月干过类似的活，技能库里有记录；错误处理自动走 wrapError；文件放进 src/services；提交信息自己按项目里的中文格式写好了。我 review 的时候只改了一个日期字段的格式。中途它想跑脚本造点测试数据，沙箱拦下来问了一声，我点了允许。

那一刻我是真觉得，前面折腾这一圈，值。

## 一个人当三个团队用的人，重点看这

我手上长期有三个活儿：一个小程序、一个后台、一堆爬虫脚本。风格完全不同，有的 TypeScript 严格模式伺候，有的是能跑就行的 Python。

手动维护 CLAUDE.md 那阵子，我干过把 A 项目的规则文件整个复制到 B 项目、忘改内容的蠢事。别问我怎么知道的，问就是那次之后我养成了检查三遍的习惯。ECC 的记忆按项目隔离，各管各的，A 的规范不会渗进 B。对独立开发者来说，这条可能比前面所有都重要，你一个人当三个团队用，最怕的就是串味。

## 到底选哪个

看情况，真的。

偶尔写一次性脚本，裸用，别折腾。项目少、规范稳、人勤快，手写 CLAUDE.md，零成本解决大部分问题。长期项目、多项目并行、或者单纯不想重复自己，上 ECC。

我现在的配置是：主力项目全装了 ECC，小脚本继续裸用，CLAUDE.md 留着当兜底，写死的规则放文件里，动态攒的经验交给 ECC。两套不冲突。

你现在是靠什么让 AI 记住自己项目的？手写规则、反复解释，还是也装了记忆类的工具？评论区聊聊，我想看看有没有更省事的野路子。

我是「AI生产力空间」，每天一个 AI 技巧，工作效率翻倍。
