# 别再无脑复制AI代码了！3步消除“认知负债”，新手也能真正掌握AI编程

去年我开始用ChatGPT写Python脚本。做运营的，写不了几行代码，但需求一堆：合并十几个Excel、自动出周报、批量改文件名。每次把需求一股脑丢过去，它唰唰写完，我复制、运行、收工。头三个月攒了小二十个脚本，一度觉得自己半只脚已经踏进AI编程的门了。

然后上个月月底，连本带利，一起还了。

那天财务把部门报表的格式调了一下，加了一列。我的脚本当场罢工，满屏红字，最扎眼的一个词是KeyError。我第一反应是去搜这词什么意思，搜完还是不知道该改哪。只能把报错原样贴回给ChatGPT，它给了一版修复，跑是跑通了，数字对不上；再贴回去，又改一版，冒出个新的报错。来回折腾了五六轮，越改越乱。兜了一圈，我退回最原始的方案，手动开Excel，VLOOKUP一个一个拉，搞到夜里十二点半。

最难受的不是加班。是那种感觉：文件夹里躺着二十个“我写的”脚本，出事的时候，我一个都不敢碰。名义上是我在用AI编程，实际上我连旁观者都算不上，顶多算个按运行键的。

周末约了个做开发的朋友吃饭，全程吐槽。他听完就回了一句，我到现在都记得：

“你这不叫会用AI，你这叫借高利贷。AI替你写的每一行你没看懂的代码，都是欠的债。平时没事，一出事，连本带利地还。”

他管这个叫认知负债。程序员圈有个老词叫技术债，说的是图快留下的烂代码；认知负债欠的不是代码库，是你自己的脑子。代码能跑，脑子是空的，这笔账早晚要还。

回家我翻了下这几个月跟AI的聊天记录，当场破案：我发给它的话，翻来覆去就一个句式，“帮我写一个××的脚本”，写完直接复制。它从头到尾都是我的枪手，而我连自己交上去的“论文”里写了什么都不知道。

后来我把用法整个改了。没什么高深的东西，就三条规矩，每一条都是拿坑换来的。

**第一步：复制之前，先让它讲人话。**

现在AI写完代码，我不急着复制，先追一句：

```
先别写新代码。你刚才给的那段，像给刚入门的新手讲课一样，分成几个小块，逐块讲清楚每一块在干什么、为什么需要它。讲完之后单独回答我：如果以后 [你要改的地方，比如：数据源从单个文件换成整个文件夹]，应该动哪几行？
```

两个细节。一是分块讲，不是逐行讲，逐行太碎，看完啥也记不住。二是“以后要改哪”这句必须问，因为你迟早要改。这句话问多了，慢慢就看出来AI写脚本的套路了，大部分脚本都是“读数据、洗数据、算、输出”四段，看懂一次，后面遇到的全是熟面孔。

**第二步：核心逻辑必须手敲，Copilot该关就关。**

这条听着有点反直觉：都有AI了还手敲，不是开倒车？

我的经验是分两种。import、读文件、导出结果这种样板代码，复制就复制了，手敲一百遍也不会变强。但核心逻辑，那个循环为什么这么写、那个if在判断什么，必须自己敲一遍。手敲会卡壳，卡壳的地方就是你“以为自己懂了”的地方。为什么这里是items()不是keys()？为什么默认值给个None？每一次卡壳，都是认知负债在当场结账。

顺便说个Copilot的坑。我以前一直开着它，打两个字母整行就补全了，手指在动，脑子在放空，爽是真爽，但那不叫手敲。现在写核心逻辑之前，我会先点VS Code右下角状态栏的Copilot图标，把自动补全暂时关掉（不同版本的菜单位置略有差别，找"Disable Completions"之类的选项就行），敲完再开。

**第三步：让AI反过来考你。这是我眼下最喜欢的一步。**

```
这段代码我已经看过一遍了。现在你来当面试官，围绕它问我3个问题，由浅入深。我先答，你别急着公布答案。等我全部答完，你再逐条对照，指出我哪里理解错了、哪里是蒙对的。
```

第一次被考，我第一题就露馅了。我一直以为df.dropna()是把表格里的空格清掉，实际上它是把带缺失值的整行直接删掉。就这一题让我后背发凉——之前那些“跑通了”的脚本里，藏着多少这种想当然？这种理解错误不会报错，它只会在某个数据很特殊的月份，悄悄给你算出一个错的数。

讲真，这套流程用下来，前期是变慢了。以前一个脚本十来分钟上线，现在光讲解加考试就得半小时起步。但我想明白了一件事：慢下来的那部分不是浪费，是把学费交在平时。真等月底报表炸了再交学费，那个利息，我体验过一次，够够的了。

也不是说现在就能从零手写什么了，差得远。但变化很实在：前两周又有一个脚本报错，还是格式变动引起的，我自己定位到了问题，改了两行，修好了。那一下的爽感，比我第一次跑通AI给的代码还强。认知负债这东西没有一夜还清的说法，但每还一笔，文件夹里就多一个我敢碰的脚本。

我是「AI生产力空间」，每天一个 AI 技巧，工作效率翻倍。

你有没有过“代码跑起来了，但我完全不知道为什么”的时刻？或者被AI写代码坑过吗？评论区聊聊，我看看还有多少人跟我一样欠着债。
