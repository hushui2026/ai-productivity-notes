# 不是Claude 5变笨了，是你喂的不对：处理长文档的4条上下文工程规则

上周帮一个同事排查问题。他把一份五十多页的合同 PDF 直接拖进 Claude，敲了六个字「有什么风险」，然后对着端出来的那碗白开水发呆——全是「该合同包含若干条款」之类的车轱辘话，没一条能用。

他问我，是不是 Claude 5 变笨了。

我说不是，是你喂的不对。

这两年大家都在卷 Prompt 技巧，可真到处理长文档这种硬活儿上，起决定作用的其实是你给 AI 看什么、看多少、按什么顺序看。Anthropic 官方管这个叫「上下文工程」，说人话就是：与其研究怎么跟 AI 说话，不如先研究给它吃什么。模型窗口越做越大，很多人觉得终于能把整份文件丢进去了，恰恰是新坑。

下面这 4 条，是我把官方文档和 claude-cookbooks 里的案例翻了一遍、再配上自己踩的坑之后，现在每次喂长文档都照着走的。都能直接抄。

## 1. 长文档先切再喂，别让它一口气吞

五十页合同整份塞进去，AI 不是读不完，是读着读着会「睁眼瞎」。模型对超长输入中间那一段特别容易漏看，业内管这个叫 lost in the middle，开头结尾记得清楚，中间几万字像没读过。

所以我的习惯是：先花几分钟翻目录，只把真正要看的部分复制出来。看财报就抓管理层讨论、财务附注、风险提示，封面、目录、法务声明全是干扰项。看合同就抓标的、付款、违约、终止条款。

切完之后先别急着提问，让 AI 先给你画张地图：

```
我给你一份合同的内容，请先只做一件事：
输出一份结构地图，每部分用一行说明它讲了什么。
先不要回答任何具体问题，等我看完地图再决定下一步。

<合同内容>
[粘贴你的合同内容，太长的话分几次发]
</合同内容>
```

地图出来，你再指着具体章节问，答得又准又省。多花这几分钟，后面能少返工不少。

## 2. 顺序放反了：文档在前，问题在后

这条最反直觉，我也是改了习惯才尝到甜头。

大部分人（包括从前的我）的操作是：先写「帮我总结一下下面的合同」，再粘贴全文。逻辑上好像很顺，先派任务，再给材料嘛。但 Claude 官方文档给的建议恰恰相反：长文档放在前面，具体问题和指令放在文档后面，效果更好。原理解释官方没细讲，我自己的观察是：问题贴着资料，模型不用隔着几万字回找任务，答非所问的情况就少了。

试下来确实如此，漏答的毛病肉眼可见地收敛了。

另外补一句：那种每次都要遵守的固定要求（「输出一律中文」「你是法务顾问」这种），别在每条消息里重复，直接写进 Claude 的 Project 自定义指令里，一劳永逸。

```
<合同>
[粘贴完整合同文本]
</合同>

请基于上面的合同回答：
1. 付款条件是哪几条？列出条款编号
2. 违约责任整体上对哪方更有利？给出依据
```

## 3. 用 XML 标签给资料贴书签

多份资料放在一起对比的时候，这招是真好用。

Claude 对 XML 标签非常敏感，这不是民间偏方，Anthropic 自家文档和 cookbooks 里都在推。把不同来源的资料用标签隔开，AI 提取信息时定位准得多，而且你还能要求它「只准引用某一份」，它不会串。

我上个月对比两份年报，就是这么写的：

```
我有两份资料，请对比其中的信息。

<去年年报>
[粘贴去年年报的相关内容]
</去年年报>

<今年年报>
[粘贴今年年报的相关内容]
</今年年报>

要求：所有结论只能来自这两份资料。
资料里没有的，明确写「资料中未提及」，不要自己脑补。
```

标签名用英文也行，`<contract>`、`<financials>` 这种，语义清楚就好。关键是把「哪段是什么」标出来，AI 引用的时候就不会张冠李戴。

## 4. 让AI先复述规则，再动手干活

这条看着最蠢，但救命。

长对话或多步骤任务里，AI 经常干着干着就忘了你一开始的要求。你说好每条不超过 30 字，它写到第五条开始放飞；你说好不要编造，它后面已经开始自由发挥。别问我是怎么知道的。

防呆写法就一招：让它动笔之前，先把硬性规则复述一遍。

```
任务：把下面的会议纪要改写成周报。

硬性规则：
1. 全部用中文，不出现英文术语
2. 每条不超过30字
3. 不编造纪要里没有的内容

动笔之前，请先逐条复述上面三条规则，确认无误后再开始改写。

<会议纪要>
[粘贴你的会议纪要]
</会议纪要>
```

看着多此一举，对吧？但 AI 一旦把规则亲口说了一遍，后面跑偏的概率小很多。我自己的体感是，加了这一步之后，「写到一半忘要求」的情况基本没再出现过。

说到底，上下文工程就一句话：AI 不是垃圾桶，别什么都往里倒。喂得干净、喂得有顺序，它给你的东西才像样。
