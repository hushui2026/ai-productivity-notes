# 大半年卡在第 30 页？用 Claude Code 把 300 页技术 PDF 变成随身导师

我桌面上躺着一本 300 多页的《架构整洁之道》PDF，老实说，买来大半年了，进度条卡在第 30 页。不是我不想看，是这种技术书啃起来太反人类了。白天上班被需求追着跑，晚上回家翻开书，看两页就开始走神，遇到个不懂的名词要去查半天，等查完连上下文都忘了。

相信不少人都跟我一样，买了一堆技术 PDF，最后全在硬盘里吃灰。

前阵子我在折腾 Claude Code 的时候，发现了一个叫 book-to-skill 的玩法。简单来说，就是把一本技术书喂给 Claude，让它把这本书“消化”成一个可以随时调用的 skill 文件。以后你看书遇到问题，或者做项目遇到卡点，直接向它提问，它会基于整本书的上下文给你解答。

这跟直接把 PDF 丢给 ChatGPT 问问不一样，我踩过坑。最开始我把 PDF 传给网页版的 AI，让它给我总结重点，结果它吐了一大堆废话，什么“这是一本关于软件架构的书”，完全没营养。后来我想让它解释书里某个概念，它回答得像是百度百科，干巴巴的，根本不结合书里的代码和上下文。

我还试过用 Kimi 那类长文本工具读 PDF。解析能力确实强，但当词典查可以，当导师不行。它缺乏主动性，你问一句它答一句，从来不会引导你思考。

后来我决定在 Claude Code 里搞本地知识库，试过用各种开源的 RAG 框架自己搭，光配环境、切分文档、搞向量数据库就折腾了我整整一个周末，最后跑出来的效果还是一塌糊涂，经常张冠李戴。直到我发现了 book-to-skill 的思路，其实就是用 Claude Code 直接读取本地文件，通过特定的 Prompt 把书里的知识结构化提取出来，生成一个专属的技能文件。

整个过程出奇地简单。

打开终端，cd 到我存放这本 PDF 的文件夹。敲 `claude` 启动交互模式。然后把准备好的 Prompt 丢给它。

```text
你是一个技术书籍分析专家。请读取当前目录下的 [你的 PDF 文件名.pdf] 文件，并将其转化为一个结构化的技能文件。

请按照以下要求执行：
1. 提取全书的核心目录和章节结构。
2. 归纳每一章的核心概念和关键论点。
3. 找出书中的关键代码示例、架构图描述以及作者强调的“反模式”。
4. 将以上内容整理成一个名为 book-tutor.skill 的 Markdown 文件，保存在当前目录下。文件内容应像一本可检索的百科全书，包含清晰的层级标题和关键词索引。
```

敲下回车后，Claude Code 开始呼哧呼哧地跑。你能看到它在终端里不断输出解析过程，从提取目录到归纳概念，大概跑了几分钟，当前目录下就多了一个 `book-tutor.skill` 文件。我打开看了一眼，结构极其清晰，连书里那些拗口的架构原则都被它梳理成了易于检索的卡片。

有了这个 skill，我的技术学习路径完全变了。

前天晚上，我重新翻开书看“依赖倒置原则”那一章。以前看到一半肯定犯困，这次我直接在终端里向 Claude 提问：“结合 skill 文件里的内容，用大白话解释下依赖倒置原则，并且举一个书里的代码反例。”

它没有像网页版那样胡编乱造，而是直接调用了刚才生成的知识库，给出的答案里带着书里的原话和页码。它告诉我，高层策略模块不应该依赖底层实现模块，而应该都依赖抽象。不仅如此，它还把书里那个关于“USB 接口和键盘”的例子翻出来给我讲了一遍。那个瞬间，真感觉作者就坐在我旁边手把手教我。

更爽的是拿它当陪练。

技术书里一般都有课后题或者案例练习，以前我都是直接跳过，因为自己做对做错根本不知道。现在我把题目贴给 Claude，我是这么跟它说的：“这是书里第 5 章的架构设计练习，我想让你当我的陪练。不要直接给我答案，先看我哪里想偏了，然后一步步反问我，引导我自己推导出正确的架构。”

它真的做到了。我发了一版我的思路过去，它先肯定了其中合理的部分，然后问我：“如果未来需要替换底层数据库，你现在的设计需要改动哪些模块？”这种苏格拉底式的追问，逼着我去翻书里的“边界”那一章，硬是把一个模糊的概念彻底搞懂了。这个交互体验，是任何长文本对话工具都给不了的。

除了答疑和陪练，我平时还会把它当全书检索器用。

做项目的时候，我突然想查书里关于“组件耦合”的论述。直接输入指令：“从 skill 文件里检索关于组件耦合的三条原则，分别在第几章，核心论点是什么，给我个一句话总结。”它迅速定位到第 13 章和第 14 章，把无依赖环原则、稳定依赖原则和稳定抽象原则提炼出来，还做了对比。我自己翻 PDF 搜关键词，还得肉眼在一堆文本里找，这套操作下来肉眼可见地顺手了，起码能省一半时间。

讲真，不是什么书都适合这么干。我拿一本小说试过，Claude 生成的 skill 基本是废的，因为小说没有逻辑结构和知识点。最适合喂给它的，是编程教材、系统架构书、甚至某种复杂框架的官方手册。只要这本书本身逻辑严密、知识点密集，转化成 skill 后的效果就极其拔群。特别是那种大部头的官方文档，转成 skill 后，你写代码遇到报错，直接让它从文档里找解决方案，比去搜索引擎里大海捞针高效得多。

如果你硬盘里也躺着几本看不完的技术 PDF，别让它继续吃灰了。花几分钟装个 Claude Code，把书变成你的专属技能库，这种“随问随答”加上“引导思考”的模式，可能会重塑你看技术书的方式。
