# 让Claude Code改个日期格式，它编了个不存在的函数：直到我写了这份CLAUDE.md

上上周被 Claude Code 气得不轻，到现在还没完全消气。

事情是这样的。我有个跑了一年多的 Python 脚本，每周自动拉数据、生成一份 Excel 周报，一直挺稳。那天我发现导出的日期格式不对，Excel 里显示成 2025/6/3，我想统一成 2025-06-03。

多大点事，对吧。我打开 Claude Code，丢了一句“把导出日期统一成 YYYY-MM-DD”。

它干了一分多钟，交回来的东西是这样的：日期确实改了，但它顺手把我整个导出模块“优化”了一遍——pandas 部分重构了，平白多出三个新文件，到处塞 try-except。最绝的是，它调用了一个叫 `safe_to_excel` 的函数。

我的代码里根本没这个函数。

它自己编的。

我指出来，它道歉、删掉、改回原样。行，忍了。半小时后我让它给某个 sheet 加一行汇总，它又来一遍：把旧代码整段注释掉，说是“保留以防万一”，又写了个不存在的工具函数，然后告诉我“已完成，运行应该没问题了”。

我手动跑了一下，报错。

那一刻我想明白了：它不是不会干活，是有一套固定的犯病模式，而且骂一次没用，过几轮它就忘，接着犯。我在终端里打字骂 AI，纯属浪费感情。

后来我去搜有没有人系统治过这毛病，翻到了 Karpathy——OpenAI 创始成员、前特斯拉 AI 总监那个 Andrej Karpathy。他吐槽过一模一样的问题，还把应对经验写成了规则，GitHub 上有人整理进 andrej-karpathy-skills 这个项目，核心就是一份 CLAUDE.md。我读完发现，我踩的坑他基本全列出来了，凑一凑正好五个。

**坑一：自作主张扩大改动。** 你让它改个日期格式，它觉得你整个模块都“有待优化”。我猜是因为模型训练时见到的代码大多是干净的、工程化的，它就往那个方向靠，完全不管你要的其实只是六行 diff。

**坑二：编造 API。** `safe_to_excel` 就是这么来的。模型分不清“看起来合理的函数名”和“真实存在的函数名”，它觉得这段代码里应该有个这样的工具，就当真有。项目命名越规范，越容易被编。

**坑三：不验证就宣布完成。** “应该没问题了”翻译过来就是“我没跑过”。你不明确要求，它默认靠“代码看起来对”下结论。

**坑四：留死代码、写废话注释。** 注释掉旧代码而不是删掉，再配一句 `# 将数据转换为DataFrame` 这种注释。听着谨慎，落到真实项目里就是垃圾，回头你自己都不敢删。

**坑五：同一个坑反复踩。** 最气人的一个。你在会话里骂它十次，短期确实收敛，但上下文一长就飘，新开会话直接归零。靠嘴纠正，治标不治本。

Karpathy 的解法说出来不值钱：别每次靠吼，把规矩写在门口。

CLAUDE.md 就是那个门口。Claude Code 每次启动会自动读项目根目录下的这个文件，相当于给它的入职须知，写一次，次次生效。我把他的规则按自己的项目改了改，直接放出来，你可以抄：

```
# 项目规则

## 改动范围
- 只做被要求的最小改动，禁止顺手重构、优化、格式化
- 想做额外改动，先问我，确认后再动

## 写代码之前
- 修改任何文件前，先读相关代码
- 不确定函数、配置、字段是否存在时，用搜索确认，禁止凭印象编造
- 项目入口：[你的常用命令，比如：python report.py 生成周报]

## 改完之后
- 必须实际运行 [你的验证命令，比如：python report.py --dry-run]，把真实输出贴给我
- 禁止只说"应该可以了"就结束

## 代码风格
- 删代码就直接删，不要注释掉留着
- 不写描述显而易见操作的注释
- 新建文件需要我同意

## 特别提醒
- [你个人最烦的行为，比如：不要加"以防万一"式的 try-except]
```

模板里空着的那行 [你个人最烦的行为] 建议认真填。每个人被气到的点不一样，我的雷区是“以防万一”式防御代码，你的可能是它老爱建新文件。提前写清楚，比当场发火管用。对了，还有个全局位置 ~/.claude/CLAUDE.md，放跨项目通用的偏好，比如“永远用中文回复”，写一次所有项目生效。

真要挑三条投入产出比最高的，我投：最小改动、禁止编造 API、改完必须自己跑。前两条直接砍掉大部分返工的来源，第三条把“它以为修好了”和“真的修好了”强行对齐。我自己用下来，以前一个小需求平均要来回折腾四五轮，现在大部分一两轮就收工。

还是改日期格式那个活，加上 CLAUDE.md 之后我重新试了一遍：diff 总共动了六行，改完它自己跑了遍脚本，把输出贴给我，末尾还问“汇总 sheet 的日期要不要也统一”。同一个模型，判若两人。

再多说一句。CLAUDE.md 管的是规矩，但有些事是手艺，比如完整的一套发版流程、code review 检查清单，全塞进去会把它撑爆。这种用 Agent Skills 更合适：在 .claude/skills/ 目录下建文件夹放说明，模型用到时才加载。VoltAgent 维护了一个 awesome-agent-skills 仓库，收录了上千个现成技能，从写 commit message 到做 code review 都有，可以直接抄来改。我的节奏是：规矩先进 CLAUDE.md，等哪条膨胀成一套流程了，再拆成 Skill。

所以整个路径就是：被气到，把气到的点写成规则，放进 CLAUDE.md，下次开工自动生效。指望模型自己开窍不现实，把你的脾气提前文档化，才是打工人该干的事。
